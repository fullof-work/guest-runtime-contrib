# EROFS patches

`series` applies the ordered patches to the original erofs-utils v1.9.1 archive, SHA-256 `a9ef5ab67c4b8d2d3e9ed71f39cd008bda653142a720d8a395a36f1110d0c432`. `0002-explicit-libgcrypt-sha256.patch` changes only `lib/sha256.h` and `lib/sha256.c`. The series does not include the optional disk index patch.

`0003-exact-chunk-read.patch` fixes chunk input reads in `lib/blobchunk.c`: check signed syscall results, retry EINTR, advance through positive short reads, and reject errors or unexpected EOF before hashing. Successful content, full SHA-256 deduplication and layout stay unchanged. The adjacent license sidecar preserves `GPL-2.0-or-later OR Apache-2.0`. `make test-erofs` relinks a private static test binary with read/fortified-read fault wrappers and checks real EINTR, short reads, EIO, EOF and partial-then-error behavior. It compares successful image bytes and extracted file contents, not just fsck status. The wrappers are test inputs only and never enter packaged tools. If a native cache lacks compilation objects, the test reconstructs them through the selected build recipe in private storage.

`0004-single-device-plan.patch` adds an optional planning output to the same native directory scanner, inode/chunk indexes and block allocator. The ordinary raw invocation retains its layout. Plan mode reads in batches of at most 1 MiB while retaining 4 KiB chunks, complete SHA-256 deduplication, a single device, no compression, no xattrs, a zero UUID and epoch timestamps. Its sparse layout contains metadata; the unique data area is represented by source references instead of a private data blob. That virtual area is Data in the final image, even though it is a hole in the layout file. No content-zero scan defines holes.

`--plan-version` reports `erofs-plan 1 sha256-4k-single-device`. `--plan=PATH` creates a private header, `PATH.sources` and `PATH.chunks` with exclusive creation; these are an internal producer/consumer contract, not an artifact format. `--plan-memory=BYTES` bounds native address space, including deduplication and inode/path tables; `--plan-bytes=BYTES` bounds the plan and materialized layout metadata. Both default to 512 MiB. Exceeding a budget or requesting unsupported output policies fails; callers must not silently fall back to raw staging.

The little-endian v1 header is 192 bytes: eight-byte `KERPLAN\0` magic; u32 version/header length; u64 features, logical length, data-area offset/length, chunk/source counts and index byte lengths; three 32-byte SHA-256 digests for metadata layout, chunks and sources; and 16 reserved zero bytes. Each 64-byte chunk record stores u64 target-relative offset, source offset and source ID, u32 length/padding and the full SHA-256 of the unpadded data. Target offsets are consecutive 4 KiB units and source IDs are nondecreasing. Each source entry has an 80-byte identity header followed by its root-relative path: ID, device, inode, size, mtime/ctime seconds, their nanoseconds, mode, UID, GID, path length and link count. Atime is excluded. The consumer checks bounds, overflow, records, identities, digests and padding; it must retain the stable source until emission and final validation finish.

`test-erofs-plan.py`, invoked by `make test-erofs`, compares reconstructed plans with actual raw output and checks extracted file content, permissions, links, empty and sparse files. The disposable static probe also injects pread EINTR, short reads, EIO, EOF and partial-progress failures into the batch path. Capability/policy and plan-byte-budget rejection are checked. The probe, reconstruction helper and injection environment are test-only and never enter release payloads.

The build explicitly defines `EROFS_USE_LIBGCRYPT_SHA256` and disables OpenSSL and multithreading. Both SHA entry points initialize Libgcrypt on first use. The single-threaded tools disable secure memory because image chunks are not secrets. Initialization or streaming-context allocation failure aborts before a digest can be used. One-shot hashing uses `gcry_md_hash_buffer`; streaming uses the SHA-256 context, copies all 32 bytes, and closes it. There is no fallback, linker wrapping, digest truncation, layout change, or CPU-specific build flag.

The adjacent `.license` maps the patch to the original file licenses: `lib/sha256.h` is `GPL-2.0-or-later OR Apache-2.0`; `lib/sha256.c` is `Unlicense`. Upstream SPDX and copyright text remain intact. Other EROFS files retain their own licenses, including the GPL-2.0-marked hashmap objects actually linked into the tools. See [license scope](../../../LICENSE_SCOPE.md).

[Libgcrypt](https://www.gnupg.org/software/libgcrypt/index.html) and Libgpg-error libraries use LGPL-2.1-or-later; their source distributions contain additional file-specific licenses and notices. Collect the actual target packages' copyright, LICENSE/COPYING/NOTICE material and source versions, rather than assigning one generic license to all their files. The native release collector records every external link input's bytes and package/source identity in `EROFS-INPUTS.tsv` and `SOURCES.tsv` and rejects missing notices. Patch bytes and sidecars must match the selected commit's local Git objects.

For source rebuilding or relinking, retain the selected guest recipe/helper, ordered patch directory, original pinned archive, both linker maps, EROFS object/archive inputs, and the exact target library source/build configuration and notices. The [native build guide](../../README.md) describes package and sysroot inputs. Rebuild with `make -C native-deps erofs` using the recorded target compiler, flags and static libraries. Release builders must supply matching source/relink materials through the existing materials contract; passing synthetic packaging tests does not establish that those materials have been provisioned.
